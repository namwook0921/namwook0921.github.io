The first approach we take is fixing an image from a single channel, and moving around an image from a different channel, and comparing the similarity of the two images. The most simple metric to compare the similarity is the Euclidean distance, which is the sum of the pixel-wise distance between the two images. A better metric is Normalized-Cross-Correlation (NCC) which is the dot product between two normalized images. A caveat is that L2 norm is a metric we would like to minimize, and NCC is a metric we would like to maximize. In my implementation, we find the minimum for the L2 norm and the negative NCC for consistency. The method of normalizing is by subtracting with mean, then dividing by the standard deviation across the whole pixels.

Cropping off the edges (10% of top, bottom, left, right in my implementation) works better in finding the right shift, because the edge of the films do not contain the clear image, but instead is usually stained in the old pictures from the early 20th century.

The naive alignment search is a great way to aligning the images from different colors channels. However, it gets more expensive as the image size increases, and first, we analyze the scale mathematically. Let's assume the height and the width of the image scales proportionately, which means the width = (ratio) * height where ratio is bounded for instance, [0.5, 2]. Then let's assign n = height and figure out how the computation for naive alignment search scales with n. The range for the search is proportionate to the n^2. Assume when taking the pictures, Prokudin-Gorskii allowed a sway up to 3 % both horizontally and vertically. Then, the number of pixels to measure the displacement is max 3 pixels for a 100 x 100 image, and this grows to 30 pixels for a 1000 x 1000 image. Therefore, for larger n, we need to search proportionately to n both vertically and horizontally, which leads the whole search grid proportionate to n^2. Second, the NCC or L2 norm both does operations for all pixels, which is also O(n^2). Therefore, as both the number of operations and the computation of the operations increase in O(n^2) scale, the whole search's time is proportionate to O(n^4) scale, roughly. Therefore, the time it takes for emir.tif which is (3209, 3702) size could be approximately 10,000 times of cathedral.jpg which is the size of (341, 390). Therefore, this motivates us to implement a pyramid search which reduces both the number of searches and the size of the image.

The pyramid search works as follows: Reduce the image in 0.5 ^ depth scale using anti-aliasing methods. Do a grid search (r^2) around the origin and find the best aligning shift. Assign this shift as a next origin, then for the 0.5 ^ (depth - 1) scaled-down image, we do a grid search around the new origin, and assign the best shift as the next origin. We repeat this step until we come back to the original image. Let's compute the approximate time complexity for this method: for each step, we do r^2 computations, and for the steps, the complexity of finding the loss is (0.5 ^ d * n)^2. Therefore, we take the sum of r^2 * (0.5 ^ d * n)^2 for d in 0, ... , depth, which adds up to approximately 4 / 3 * r^2 * n^2. Therefore, we reduce the time complexity of the search from O(n^4) to O(n^2). Adding to this, the size of the grid becomes smaller than the naive align search as every new origin, we know that the best aligned is close around to it. In practice, I used 31 * 31 grid (from -15 to 15) for the naive search, and 7 * 7 grid (from -3 to 3) for the initial pyramid search which gives us a ~20x speed-up.

namwook_lee Failure Modes of Raw Pyramid Search

In Emir's photo, he is wearing a robe in a blue background color, with green and red patterns. This makes taking the naive l2 or the NCC norm not a great metric. Imagine a red pattern in the blue robe and denote them as set R, B. When normalized, for the blue channel, the pixel values will be positive in B, negative in R. For the red channel, it will be negative in R, positive in B. So a perfectly aligned picture, will result in a negative NCC which is different from our optimize to maximize the NCC.

Then why can't we just minimize the NCC instead? Then, the background or other features that do not have such a vivid color would score high NCC. Therefore, there are two regimes with different objectives: for colors that include all three color channels, NCC has to be maximized, and for single-colored parts, NCC has to be minimized. This mechanism works similarly for l2 norm, since in the areas with a single color, the gap between the different color channels increase.

Also, fixed hyperparameters for pyramid search introduces a problem. As we are using a fixed depth for images of different scale, we require a depth of 6~7 to find a good estimate for the .tif images. However, this results in image 2 which is a heavily misaligned version of the monastery.jpg. Too much downsampling blurs the image and results in a very bad shift for the monastery.jpg file.

namwook_lee Gradient Magnitude Matching & Size-Aware Parameters for Pyramid Search

To overcome the issue that happens with Emir's photo because different brightness for each channels, we take the approach of using the gradient magnitude instead of using the raw pixel values of each channel images. The gradient magnitude finds the edges in the pictures, and isn't signed because it's the magnitude. Therefore, it doesn't have conflicting objectives like in the raw pixels - we can aim to maximize the NCC. The gradient of emir is shown in images 2, 3, 4. Gradient is normally defined in a continuous function, but as the pixels are a very small unit, we use a numerical approximation as following: grad_x is obtained by shifting the image by 1 pixel and subtracting it from the original image. Similarly, grad_y is obtained, then we sum the square of the two and take a square root to obtain the final gradient magnitude. We then do pyramid search using NCC loss to obtain the aligning shift for the channel images and reconstruct the image.

For the parameters, we introduce flexible parameters that optimizes the pyramid search using a simple method. The first intuition is that the depth of the pyramid search should be proportionate to log scale of the height (or width) of the image. Since the scaling factor of the image is 2, we take 2 as the base of the log, and calculate depth = log2(max(height, width)) - 5. 5 is chosen as a hyperparameter so that the coarsest image is at least 64px wide and tall.

The second intuition is that for deeper depths, we can afford more searches. Since the images get smaller and the pixels become less by a scale of 4 each downsampling, the main bottleneck in complexity is the first layer where the image is the biggest. Therefore, we linearly increase the range of grid exploration as the image gets downsampled.

The collection of the above strategies result into a single reconstruct() function that takes in different sized images, and flexible inputs for the difference metric (ncc, l2_loss, etc.) and also the preprocessing method (gradient magnitude, identity, horizontal/vertical edges, etc.).
